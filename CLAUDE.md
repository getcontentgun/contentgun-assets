# CLAUDE.md

## What this is

The asset module of ContentGun: a FastAPI service that renders social media cards to PNG, and
carousels to one PDF. A request carries text, the service fills a Jinja2 HTML template, loads it
into headless Chromium and screenshots it. There is no AI in the rendering path, and without
storage nothing is stored: the PNG is the response body. With an S3-compatible bucket the service
also stores results behind URLs, takes uploads through signed URLs and reads the bundles of the
tenants from the bucket, see `docs/storage/README.md`.

It replaced the Gemini image nodes in the contentgun n8n flows, which produced non-deterministic
cards with typography errors.

## Commands

```
.venv/bin/pip install -r requirements-dev.txt     # deps
.venv/bin/python -m playwright install chromium   # browser
bin/development                                   # checks, then uvicorn
.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8010 --reload
bin/test                                          # ruff, then pytest
bin/test --suite -k render                        # pytest only
.venv/bin/pytest -q
.venv/bin/ruff check . && .venv/bin/ruff format --check .
docker compose -f compose.dev.yaml up --build     # the service in a container
docker compose -f compose.dev.yaml --profile storage --profile remote up --build   # with the MCP server and its gateway
bin/smoke assets <image>                          # start a built image and send one request
bin/release                                       # bump the version, test, tag; CI publishes both images
python3 scripts/new_api_key.py                    # a key and its hash for the tenants file
docker compose -f compose.dev.yaml --profile storage up -d storage   # RustFS on 127.0.0.1:9010
.venv/bin/python scripts/setup_storage.py         # create the bucket, set its lifecycle rules
.venv/bin/python scripts/put_bundles.py <folder>  # the bundles of one tenant into the bucket
.venv/bin/python mcp/remote_server.py            # the remote MCP server, settings in docs/mcp/remote.md
```

Startup prerequisites: `.env` exists with a key in `API_KEYS` or a tenants file in `TENANTS_FILE`,
the tenants and their bundles are valid (the built-in ones in `bundles/`, those of the tenants in
`BUNDLES_DIR`, or in the bucket), the storage settings are complete or all empty, and Playwright's
Chromium is installed. A broken bundle or tenants file, incomplete storage settings or an
unreachable bucket that should hold the bundles fail at import time with a message naming the file
or the setting; a missing Chromium fails when the lifespan starts.

| `bundles/demo/_base/` | Shared skeleton and CSS of every template of the demo bundle. Not a template: the registry skips it because of the leading underscore |

`app/rendering.py` is shared by the render, document and debug routes on purpose: the browser
screenshots and prints exactly the HTML the debug route serves, so the design preview cannot drift
from the output.

## The demo bundle

`bundles/demo/` is the only bundle in this repository, and so the only built-in one: a neutral
design in slate and amber with Space Grotesk headlines, Inter for every other text and JetBrains
Mono for code, whose design, font sources and measured limits are in `bundles/demo/README.md`. The suite tests it, and
every template of it extends its `_base/`. Bundles of a brand or a customer belong to a tenant and
live outside the repository, in the tenant's folder under `BUNDLES_DIR`.

The field is called `handle` rather than by position, so moving it in a template does not make the
API lie. The handle is a plain request field: the service keeps no account directory and never
fills one in, so a card can only carry the identity its caller sent.

## Things that will bite you

- **Fonts must be data URIs, not `file://`.** After `page.set_content()` the document sits on an opaque origin. Font requests are CORS requests, so a `file://` URL is blocked and Chromium silently falls back to a system font. The card would still render, just wrong.
- **`document.fonts.load()` is called explicitly in the template.** Because the faces carry a `unicode-range`, a face that no visible character needs is never loaded. The bundle's check list is passed into the page as `font_checks`, so Python and JavaScript agree on what must be there.
- **The checks of a bundle must mirror what its CSS actually draws.** A check for a weight no rule uses passes on a substituted or synthesised face and stops meaning anything. The registry refuses to start when a check names a weight no face covers, but it cannot see what the CSS draws. When a template changes font, update the checks in its `bundle.toml`: in `demo`, every template draws Space Grotesk 700 for the headline, `quote` also for the author, and Inter 400 for every other text, and `code` draws JetBrains Mono 400 for the code and the file name, so all three are checked. The checks belong to the bundle, so every card of `demo` loads the mono face, which costs two small files per page.
- **A template only gets the fonts of its own bundle.** The page embeds only that bundle's faces, and `capture()` hands only that bundle's checks to the browser, so a template that draws a family of another bundle renders in a fallback font, and with `STRICT_FONTS` fails with `500`.
- **A face of a variable font declares the full range of its weight axis.** `demo` declares Space Grotesk `300 700` and Inter `100 900`, the ranges the files really span. Narrow a declaration and a request for a weight outside it is silently clamped to its nearest end: the text turns lighter or bolder than the CSS asks, and every check still passes.
- **`document.fonts.check()` alone proves nothing.** It answers true for a family that has no `@font-face` at all, because the browser is content to substitute. `app/browser.py` therefore pairs it with a loaded `FontFace` of the same family; drop that pairing and the strict-font gate silently becomes a no-op.
- **The headline needs vertical padding.** Space Grotesk's inline box is 1.27em tall while `.headline` sets `line-height: 1.08`, so without `padding: 0.12em 0` the first and last line spill out of the h1's border box. That both shaves accents and makes `scrollHeight` permanently exceed the box, which pins the fit-text search to its 40px minimum on every card. A bundle with another headline font has to measure its own value.
- **The image and the icon are deliberately not template fields.** `resolve_fields()` caps every declared field at 200 characters, which no real image survives. Each travels as its own top-level request key, `image` or `icon`, is validated in `app/images.py` and reaches the template as the separate `image` or `icon` context value. Move either into `fields` and every request carrying one breaks. `icon_color`, by contrast, is a normal field of `carousel-content`, typed in `RenderRequest` so that only `accent` and `text` get through.
- **Code is a capability like the image, not a template field.** `code`, `language`, `line_numbers` and `highlight_lines` are reserved keys, because `resolve_fields()` would cap code at 200 characters and refuse the boolean and the list. A template takes code with `code = true`, then requires it in every request, and needs a `[code_sample]`, which the registry runs through `check_code()` at startup like a request. `app/code.py` counts lines and columns after `normalize()`, so the messages, `highlight_lines` and the card's line numbers all count from the first line that is left. `SNIPPET` in `tests/conftest.py` is the smallest template with code.
- **Every line of code is a `<span class="line">` with nothing between the spans.** The bundle's CSS sets them `display: block`; a newline between block spans would add an empty line under `white-space: pre`, and an empty block collapses, which is why an empty line carries one space. The lexer gets the code with a trailing line break that `_highlight()` drops again: line-based lexers, such as the one for diffs, match a line only together with its line break, and without one the last line comes back as unhighlighted error tokens, which the check that the tokens add up to the code does not catch.
- **A caller's SVG is always an `<img>`, never inlined.** As an image Chromium runs no script in it and loads nothing it references; inlined into the page it would run its scripts and fetch its external references from the server's network. The tint is therefore an SVG filter on the `<img>`, `#tint` in `carousel-content`: flood with the color, composite `in` with `SourceAlpha`. Keep `color-interpolation-filters="sRGB"`, or the color drifts, and keep the filter's `<svg>` out of `display: none`: there the filter stops applying and the icon renders black while the endpoint still answers `200`. A CSS mask would tint as well, but it is a resource of its own that the readiness gate cannot wait for. In a PDF, Chromium prints the filtered icon as a 300 dpi bitmap.
- **Icons are parsed with the stdlib, which is only safe on expat 2.4.1 or newer.** Older expat expands nested entities without limit. `verify_xml_parser()` refuses to start on such a build, next to the font check; `ElementTree` resolves no external entities on any version.
- **The render and debug routes dump the request with `exclude_unset=True`.** `RenderRequest` types `subline` and `handle` as optional fields, so a plain `model_dump()` hands `resolve_fields()` a `subline: None` the caller never sent, and `resolve_fields()` rejects undeclared keys before it maps `None` to a default. Without the flag every template that does not declare `subline`, today the three carousel templates, answers every request with `400` "Field 'subline' is not accepted". An explicit `"subline": null` still gets through and is rightly rejected.
- **A fallback image is embedded as a data URI too, and cached.** The same opaque-origin rule that rules out `file://` for fonts rules it out for images, so `file_data_uri()` inlines the bytes; it is cached because a photo can be half a megabyte and never changes at runtime. A fallback that a template declares but that is missing from its bundle's `assets/`, or not a PNG, JPEG or WebP file, fails at startup: the registry runs every fallback through `file_data_uri()` once, next to the other template validation.
- **Every image is decoded before the page reports ready.** `_base/base.html.j2` chains `img.decode()` for every `<img>` of the page after the fonts, the backdrop of `card-image` included. A failed decode still marks the page ready, so a broken image gives a card without it instead of a 504; the broken `<img>` is removed, so it leaves no gap and does not switch on the content slide's graphic mode. Removing the chain lets the screenshot catch the card before the image is painted.
- **Hyphenation is done in Python, and the CSS must not fight it.** `app/hyphenation.py` inserts soft hyphens because Chromium's `hyphens: auto` relies on dictionaries that are present on macOS and absent in the Linux headless shell, which would make development and production break words differently. The templates therefore must not set `overflow-wrap: anywhere` or `break-word`: both turn every position into a break opportunity, and Chromium then prefers the fuller line over the offered hyphen, so the soft hyphens are silently ignored. What keeps an unbreakable run inside the card instead is `MAX_UNBROKEN`, which chops anything longer than 12 characters that has no break opportunity at all.
- **Every fitted field must go through `| hyphenate`, or `| highlight`, which hyphenates every part around the marked word.** The filter is also where `MAX_UNBROKEN` chops long runs, and since the templates may not set `overflow-wrap`, that chopping is the only thing that keeps an unbreakable run inside its box. A fitted field without the filter pins the fit-text search to its floor as soon as it holds a long unbroken run, and is clipped at the side. Code is the one fitted text that never goes through it, because a soft hyphen would change the code: its caps of 14 lines and 48 columns take the place of `MAX_UNBROKEN`, and the template sets `white-space: pre`.
- **The character limits and the minimum font sizes are one system.** The caps in `app/schemas.py` (headline 140, subline 200, handle, topic, author and filename 60, role 80, pagination 16), the 200 that `resolve_fields()` puts on every other field, and the 14 lines of 48 columns that `app/code.py` puts on code, are tight enough that running text never reaches a floor (`--headline-min`, `--subline-min`, `--body-min`, `--cta-min`, `--quote-min`; code may sit at `--code-min`, since a full block of code is its tallest text), and that even the tallest text a field can hold still fits at its floor. That text is a run of wide capitals such as `W` at the full limit: `hyphenate()` chops it every 12 characters, and only below a certain size do chunks share a line, at 41px two of them in Space Grotesk 700 and at 24px three in Inter, which is where the floors of `demo` sit. Measured in the renderer, a 140-character headline of running text lands at 49px or more and a 200-character second field at 33px or more on every template of `demo` in every format it offers, and 140 × `W` lands between 41px and 45px without clipping. Clipping is therefore unreachable through the API today, short of text that is mostly literal newlines: each one costs a full line at any size, which no character limit accounts for. Raise a cap, raise a floor, shrink a box or switch to a wider font, and clipping becomes reachable — silently, because the endpoint still answers `200` with a cut-off card. `1:1` leaves the least room, which is why `demo` shrinks the gaps there and the cover's swipe button; `topic` is capped at 60 because the label is not fitted and a longer run of capitals would squeeze the cover's headline below its floor; on `demo/quote` the same holds for `author` and `role`, which wrap unfitted and take their room from the quote, the most with a portrait next to them. The content slide's image or icon belongs to the system as well: with one, the headline and body boxes shrink so that `--icon-size` stays free with both fields at their limits, and running text in the headline still lands at 49px or more. Re-measure both formats when you touch any of these, with and without a graphic. The numbers are documented in `docs/render.md`, and `tests/test_text_limits.py` fails once a run of `W` at the limits no longer fits. A template whose design needs tighter caps sets them in the `[limits]` table of its `template.toml`, which `resolve_fields()` enforces on top of the typed ones; the `SHOWCASE` template in `tests/conftest.py` covers that, together with the `highlight` and `percent` filters and the `9:16` format, which no template of `demo` uses.
- **The readiness gate is `document.documentElement.dataset.ready`.** The screenshot waits for it. It is set only after the fonts resolved, every image decoded and the fit-text pass ran, across two animation frames. Removing the wait produces cards with unfitted text.
- **The graphic mode of `carousel-content` is one rule per format.** `:root:has(.graphic)` is exactly as specific as `:root[data-format="1:1"]`, so one shared rule would override the `1:1` values by source order; `template.css` therefore writes `:root[data-format="4:5"]:has(.graphic)` and its `1:1` twin. In that mode the headline box does not shrink: the image is the only stage item that gives way, otherwise the fit pass measures a squeezed headline box and picks a smaller headline than the text needs. `demo/quote` hands the headline's room to the quote the same way, with `:root[data-format="…"]:not(:has(.headline))` once per format.
- **The fit pass measures the element against the box's client area.** `fit()` compares the element's `scrollWidth` and `scrollHeight` with the box's `clientWidth` and `clientHeight`, which include the box's padding, so a fitted box keeps its distance with a margin, as the code box of `demo/code` does. That box paints the band of a highlighted line into its margin through `overflow: clip` and `overflow-clip-margin`; under the `overflow: hidden` of a plain `.fit-box` the band's outer `box-shadow` is cut at the box, and the band stops short of the window's edges. `test_a_short_snippet_is_set_at_the_code_maximum` fails once anything pins the code to its floor.
- **With a centered stage, `scrollHeight` misses overflow.** Half of an overflow goes above the stage's top edge, where `scrollHeight` does not count it, so `tests/test_text_limits.py` compares the rectangles of the stage's items with the stage instead.
- **Fit-text runs after `document.fonts.ready`.** Text metrics before that are the fallback font's and the binary search would pick the wrong size.
- **A `data-fit` element needs both `--<name>-min` and `--<name>-max`, in px.** `_base/base.html.j2` derives the names from the attribute value and skips an element whose pair is incomplete, with a `console.warn` that only the debug route's browser console ever shows: the text keeps its CSS size, can be clipped by its box, and the endpoint still answers `200`. The values are read with `parseFloat`, so `2rem` would silently mean 2px.
- **The images and icons of a document share one budget.** Without the old ban on images in `/v1/document`, a request could otherwise carry 20 images of `MAX_IMAGE_BYTES` each. The router adds up their estimated sizes before anything is decoded and answers `413` above `MAX_IMAGE_BYTES` for the whole document; uploads count with their stored size, URLs with the bytes that arrive, once for every slide that uses them.
- **A PDF page needs screen media and printed backgrounds.** `render_pdf` switches the page to screen media and prints with `print_background=True`; without them every card comes out on white. `page_ranges="1"` keeps a slide on one page. A document is one print per slide, joined by `app/document.py`, because every slide is an HTML document of its own with its own `:root` variables, so they cannot share one print.
- **`--force-color-profile=srgb` is not optional on macOS.** Without it Chromium renders through the display profile and every color comes out shifted, the exact values the pixel tests check included.
- **The Playwright pin and the browser revision belong together.** `playwright==1.62.0` in `requirements.txt` decides which Chromium `playwright install` fetches, and `docker/assets.Dockerfile` builds on `mcr.microsoft.com/playwright/python:v1.62.0-noble`, whose browsers belong to the same version. Bump both together; `tests/test_docker.py` fails when they drift apart.
- **`.dockerignore` is a list of what the builds may see.** Everything else is excluded, `.env` and a tenants file included, so a file a Dockerfile is meant to copy, as they copy `bundles/` and `mcp/`, has to be added there as well; `tests/test_docker.py` checks every `COPY` of both Dockerfiles against it.
- **Compose resolves the whole file before it applies profiles.** A required variable (`${VAR:?…}`) in a service of the profile `remote` would stop every plain `up`, so the file only uses `${VAR:-}` and the MCP server names a missing setting itself.
- **The service `mcp` gets its settings one by one.** `env_file: .env` would hand it `API_KEYS` and the keys of the bucket, which it must not hold. `PUBLIC_FILES_URL` of the service and `MCP_PUBLIC_URL` are both interpolated, so an address exported in the shell wins over `.env`.
- **The gateway passes the original `Host` on.** `/mcp` takes requests only for the host of `MCP_PUBLIC_URL`; Caddy's `reverse_proxy` keeps `Host` as it came, and a proxy that rewrote it to `mcp:8020` would get `421` for every request.
- **The base image of the MCP server is pinned by tag and digest.** Slim tags are rebuilt in place; a bump changes both in the `FROM` line, and `docker buildx imagetools inspect` shows them.
- **Compose blanks `BUNDLES_DIR` and `TENANTS_FILE`.** `env_file: .env` passes every variable of `.env` into the container, so a path of the host there would reach a container that has no such path; `environment:` wins over `env_file:`. Blank works because an empty path setting counts as unset, see below.
- **An empty path setting counts as unset.** `Settings` turns a blank `BUNDLES_DIR` or `TENANTS_FILE` into `None` in a validator. Compose and `tests/conftest.py` rely on that to override a line in `.env`; pydantic-settings' `env_ignore_empty` would not do, because it skips the blank variable and falls back to the very line in `.env` it was meant to override.
- **Relaunching Chromium happens outside the per-render timeout.** A cold start inside the render budget would bill the launch to whichever request triggered it and could return 504 for a perfectly good template.
- **`template.css` is read on every request, the font CSS once at startup.** The CSS is a few kilobytes and the design loop depends on re-reading it; the base64 font blob is 250KB, never changes at runtime and is built by `load_font_set()` when the bundle loads. A changed font file needs a restart.
- **`_base/base.css` goes through Jinja.** The skeleton pulls it in with `{% include %}`, so `{{`, `{%` and `{#` in it are template syntax and either break the render or vanish from the CSS. It also reaches the page through Jinja's template cache, kept fresh by `auto_reload=True`, not through the uncached read that `template.css` gets; turn `auto_reload` off and every edit to `base.css` or a `.j2` file needs a restart.
- **A folder whose name starts with `_` or `.` is neither a bundle nor a template.** The registry skips it in the bundle root and inside a bundle, where it also skips `fonts/` and `assets/`; that is how `_base/` holds shared files without a `template.toml`. A template given such a name does not fail at startup: it is missing from `GET /v1/templates`, and every request for it is a `400` for an unknown template. Every other folder must follow the naming rule, `^[a-z0-9][a-z0-9-]*$`, or the start fails.
- **Every bundle has a Jinja environment of its own, and its loader stays inside the bundle.** `{% extends "_base/base.html.j2" %}` therefore names the skeleton of the template's own bundle. Jinja refuses `..` in a template name, and `BundleLoader` refuses a file whose real path leaves the bundle, as through a symlink; `inline_svg()` and `fallback_image` apply the same check to the bundle's `assets/`. A skeleton two bundles share is copied into both: there is no include across bundles.
- **Template ids are `<bundle>/<template>` everywhere.** The render, document and debug routes, `GET /v1/templates`, `/health`, `DEFAULT_TEMPLATE` and the `default_template` of a tenant speak only ids, and a bare template name is an unknown template. The PNG's file name joins the two with a hyphen, `demo-card_4x5_<id>.png`, because a `/` cannot be part of it.
- **Every tenant has a registry of its own, built from shared bundles.** `load_tenants()` loads the built-in bundles once and every tenant's folder once, and hands each tenant a `TemplateRegistry` of the bundles it may use, with its default template. The `Bundle` objects of the built-in bundles are the same in every registry, so changing one, as `test_undeclared_font_fails_loudly` does with its fonts, changes it for every tenant. `TemplateRegistry.load()` is the plain variant for one flat folder, which the tests and `bin/test` use.
- **A template of another tenant is a `400` for an unknown template, never a `403`.** Each route works with the registry of its tenant only, so a foreign id is simply missing, and the "Available" list of the message names the caller's own templates. A `403` would confirm that the id exists elsewhere.
- **`/health` lists the built-in templates only.** It needs no key, so it must not name a tenant or a template of one; `TenantDirectory.builtin_ids` is what it shows.
- **`authenticate()` compares against every stored hash without stopping at a match.** The time a request takes must not tell which key, or which tenant, matched. Keys are stored as SHA-256 hashes only, which is enough for keys with 256 random bits; the `sha256:` prefix in the tenants file is what tells a hash from a pasted key, since a key from `openssl rand -hex 32` is 64 hex digits too, and the startup message for a bad entry leaves the entry out.
- **The internal key needs `X-Contentgun-Tenant`; a key of a tenant ignores it.** Only `INTERNAL_KEY` may name the tenant per request. Were the header honoured for every key, any tenant could act as any other.
- **A bundle of a tenant must not share a name with a built-in one, and every folder in `BUNDLES_DIR` must belong to a tenant.** Both stop the start: the first so that an id means the same template for everyone, the second because a bundle folder left right in `BUNDLES_DIR`, the layout before tenants, would otherwise silently disappear.
- **Storage is all or none.** `storage_settings()` stops the start when some but not all of the five S3 settings and `PUBLIC_FILES_URL` are set. A blank value counts as unset, which the suite relies on to pin all six to empty.
- **boto3 sends checksums only where the API requires them, and addresses buckets by path.** botocore 1.36 and later adds CRC32 checksums to every upload by default, which S3-compatible stores reject or mangle; `S3Storage` sets `request_checksum_calculation` and `response_checksum_validation` to `when_required`, and path-style addressing needs no DNS name per bucket. `tests/test_storage.py` pins both.
- **Every storage call blocks, so it runs in a thread.** boto3 is synchronous: `app/files.py` and `app/reloading.py` call the storage through `asyncio.to_thread`, and `StreamingResponse` iterates the body of `/o/…` in Starlette's thread pool. A direct call from a route would stall the event loop, every render included.
- **The storage method is `keys`, not `list`.** A method named `list` shadows the builtin in the class body, so the annotation `-> list[str]` of every method after it fails at import.
- **The expiry lives in the object's metadata and is checked on every access.** `expires-at` holds Unix seconds; an object without it, one put into the bucket by hand for instance, is never served and never usable as an upload. The lifecycle rule of the bucket only frees space, it does not make anything expire.
- **`/o/…` takes its `Content-Type` from the file name, never from the bucket.** Only `.png` and `.pdf` names under `outputs/` match its pattern, so nothing else in the bucket can ever be served on the service's domain, as HTML for instance.
- **An upload token is checked by its signature first, and only then for its expiry.** It is `<tenant>.<upload id>.<expiry>.<signature>`, HMAC-SHA256 with a key derived from `S3_SECRET_KEY`, so new S3 credentials invalidate the upload URLs handed out before. That a URL took a file already is checked with a `head` before the `put`: two uploads racing on one URL may both land, and the later one wins.
- **Uploads are classified when they arrive and checked again when they are used.** `classify_upload()` runs the checks of a request's image or icon, and `resolve_upload()` turns the bytes into a data URI through the same `image_data_uri()` and `icon_data_uri()` as base64 in the body, so a changed object in the bucket cannot reach a page unchecked.
- **`resolve_render()` is `check_render()` and then `finish_render()`.** The first is synchronous and needs neither the bucket nor the network, so every refusal that needs neither comes before an upload is read or a URL fetched; the second reads the upload or fetches the URL. The debug route uses the synchronous parts, `resolve_image()` and its siblings, and takes no uploads and fetches nothing.
- **A document measures its uploads before it fetches them.** `upload_size()` reads only the metadata of each upload, so the shared budget of `MAX_IMAGE_BYTES` stops a request before twenty large uploads are pulled into memory.
- **A URL is fetched from the address that was checked, never by its name.** `RemoteImages._hop()` puts the checked IP into the URL and the host name into `Host` and the `sni_hostname` extension, so TLS still checks the certificate against the name. Hand httpx the URL with its name and it resolves the name again, which reopens DNS rebinding; drop `sni_hostname` and every certificate check fails against the IP. Each hop resolves once, refuses the URL if any address is not allowed, and connects to the first one.
- **`is_global` is not the address check.** Python 3.13 counts multicast, NAT64 (`64:ff9b::/96`), IPv4-compatible (`::/96`) and site-local (`fec0::/10`) addresses as global, and Python 3.12 in the image judges IPv4-mapped addresses by their IPv6 form. `FORBIDDEN` in `app/fetching.py` lists every range, and `allowed()` refuses multicast and reserved addresses on top; `tests/test_fetching.py` tries one address of every range, in the URL and as a DNS answer.
- **The httpx client lives for one hop, with `trust_env=False` and `follow_redirects=False`.** A pooled connection to the same IP would carry the next host of a redirect over a TLS session verified for the previous one, a proxy from the environment would make the connection instead of the client, and httpx following a redirect itself would skip the check of the target. `fetch()` follows at most `MAX_REDIRECTS`, each target through `checked_url()` and a lookup of its own, all within `TIMEOUT_SECONDS`.
- **The body of a URL is read raw, with `Accept-Encoding: identity`.** `aiter_raw()` counts the bytes that arrive; `aiter_bytes()` would decompress first, so a small gzip bomb would grow in memory before the limit sees it. `Content-Length` only ends a fetch early, it never lets one through.
- **httpx logs every request URL at INFO.** `app/fetching.py` raises the `httpx` logger to WARNING, because the URL of a caller may carry a token. `test_no_url_and_no_address_is_logged` fails once a URL, a host or an address reaches the log.
- **A document checks every slide before it fetches, and its fetches share one budget.** `check_render()` runs for all slides, then the formats are compared, and only then `_fetch_urls()` fetches each URL once, `CONCURRENCY` at a time, in a `TaskGroup`, so the first error cancels the other fetches. `Budget` counts the bytes of all of them as they stream, from what base64 and uploads left, each URL once per slide that uses it: fetched once, a URL still becomes a data URI in every one of those slides, and counted once, 20 slides with the same 8 MB URL would pass. Its `OverBudget` is the one error that is not numbered with a slide.
- **The debug route never fetches.** Its `image_url` and `icon_url` go into the page as they are and the designer's browser loads them; route them through `RemoteImages` and the preview of a local image stops working.
- **No test may reach the network.** `create_app()` without `remote` builds a `RemoteImages` on the system resolver and a real transport. A test that sends a URL builds its app with `FakeWeb.remote()` from `tests/fake_web.py`, a resolver of its own over an `httpx.MockTransport`. A fake answer needs `response()` from there: an `httpx.Response` built from `content` reads its body at once, and `aiter_raw()` then finds nothing.
- **The bundles of the tenants come from the bucket only while `BUNDLES_DIR` is empty.** Set it, and the folder wins even with storage; that is how bundles are worked on locally while outputs and uploads go to a bucket.
- **A reload swaps `app.state.tenants` in one assignment, after everything is validated.** Requests reach the directory through the auth dependency, so one that started earlier finishes with the registry it began with. `BundleCache` keeps the local copy before the current one for such requests and deletes older ones; a reload that fails discards only its own copy.
- **Messages about bundles from the bucket name the key, not the local copy.** `BundleCache.in_bucket()` replaces the path of the copy in every message of `load_tenants()`. A key with `..`, `.`, an empty part or a backslash stops the copy before anything is written.
- **`TenantSource` keeps what the tenants were loaded from.** `load_tenants()` attaches it to the directory, so a reload of an app built from a `TenantDirectory`, as every test app is, reads the same tenants file and folders again.
- **The debug routes take the tenant as a query parameter.** They are unauthenticated, so no key names it. With one tenant it is optional and the links of the overview leave it out; with several, `/v1/debug` lists the tenants and `/v1/debug/html` requires it.
- **The suite pins `API_KEYS`, `TENANTS_FILE`, `INTERNAL_KEY`, `BUNDLES_DIR`, `DEFAULT_TEMPLATE` and the storage settings in `tests/conftest.py`,** the paths, the internal key and the storage to blank, so a variable in the shell or in `.env` cannot change what it tests. Storage in the tests is `MemoryStorage` from `tests/memory_storage.py`, behind `files_of()`; `storage_app` holds the three tenants of `tenant_app` with it. The tests address templates through the id constants there, build small bundles of their own with `write_bundle()`, which borrows a font file from the bundle under test, and build apps with tenants of their own through `tenants_for()`; `tenant_app` holds three tenants with a bundle each, one of which leaves out `demo`.
- **A SIGKILLed uvicorn leaves Chromium behind.** Clean up with `pkill -f chromium_headless_shell`.
- **`mcp/` is a plain folder, not a package.** The desktop app runs the folder directly, which puts it on the import path, so its modules import each other flat (`from config import ...`). An `__init__.py` in it would make it a package named `mcp` that shadows the SDK of the same name; without one, Python prefers the installed SDK. Its module names must therefore not collide with `app`, `tests` or an installed package, and `pyproject.toml` keeps `mcp` third-party for ruff and puts the folder on pytest's path.
- **stdout belongs to the MCP protocol of the local server.** Nothing it runs may print: a stray line corrupts the stream and the desktop app drops the server. `main()` logs to stderr, which the app collects in `~/Library/Logs/Claude/mcp-server-contentgun-assets.log`.
- **`mcp/` must not import from `app`.** `app.config` reads this repository's `.env` and `app.main` loads the tenants and their bundles at import time; the MCP server runs elsewhere and talks to the service over HTTP only.
- **`render_carousel` needs a bundle,** in the local server from its `bundle` parameter or `ASSETS_BUNDLE`, and it refuses before any request without one; the remote server takes the parameter, or else the one bundle of the tenant with all three carousel templates, and asks for the parameter when there are several. It renders `<bundle>/carousel-cover`, `<bundle>/carousel-content` and `<bundle>/carousel-closing`, so a bundle offers carousels by having templates of these names. The tool descriptions name no template; hints for a single template belong into its `description`.
- **`MCPServer.call_tool()` raises in-process.** A `ToolError` becomes an `is_error` result only over the protocol, so the server tests go through `mcp.Client`, not through `call_tool()` directly. Over the protocol the SDK puts `Error executing tool <name>: ` before the message, which `tests/test_mcp_remote_tools.py` strips.
- **The limits in the MCP tool descriptions mirror `app/schemas.py` and `app/code.py`.** The model never reads the docs, so `LIMITS` in `mcp/cards.py`, which both servers put into their descriptions, repeats every cap, the 14 lines of 48 columns of code included; `tests/test_mcp_server.py` fails when the two drift apart.
- **`mcp/cards.py` is what both servers share:** the limits, the hint on code and the descriptions of its parameters, the carousel models and the request bodies of a card and a carousel. `tools.py` keeps only the file handling of the local server, and its `CarouselSlide` extends `SlideText` from there, which leaves the JSON schema the model sees unchanged.
- **`extra_fields` of the remote server must not set a key of `RESERVED_KEYS`.** `RESERVED` in `mcp/remote_tools.py` covers every key of `app/schemas.py`, `output` included: a tool call that set `output` would turn the stored result into a file the tool cannot pass on. `tests/test_mcp_remote_tools.py` fails when a key is missing.
- **The remote server fetches its previews from the service, not from the public URL.** It renders with `output: url`, gives the model the public URL and reads the PNG back through `ASSETS_BASE_URL` and the path of that URL, without a key; `AssetsClient.stored_file()` refuses any path outside `/o/`. Failures it reports name no internal address: the `Wording` of `REMOTE` replaces the local sentences, which point at `bin/development` and `ASSETS_API_KEY`.
- **A result reaches the chat of claude.ai only as a file.** claude.ai does not put the preview of a tool result into Claude's answer; the user sees the text Claude writes and the files it shares. `render_card` and `render_carousel` therefore end their answer with a `curl` command, and `SHOW_IN_CHAT` in their descriptions tells Claude to run it in its code execution environment and share the downloaded files, which claude.ai shows in the chat. That needs the host of `PUBLIC_FILES_URL` under "Additional allowed domains", as an upload does. Drop the command or the description, and the cards are back to links.
- **The remote MCP server signs instead of storing.** Client ids, client secrets, access and refresh tokens are HMAC-signed with keys derived from `MCP_SECRET` and `MCP_PUBLIC_URL`, one per purpose (`mcp/signing.py`), so a restart signs nobody out, and a token of another purpose or another server is refused. A new `MCP_SECRET` invalidates every client, and Claude answers with `invalid_client` until the connector is reconnected; signing everybody out on purpose is `MCP_SESSIONS_AFTER`.
- **The answer to a registration is the object `register_client()` changed.** The SDK hands the provider the new client and returns that same object, which is how Claude learns the signed client id and the secret. A provider that builds a new object registers a client Claude never hears of. `get_client()` rebuilds the client with the scope `cards offline_access`: a client without a scope gets every scope refused at `/authorize`.
- **A client id needs its random part.** Besides its time, its auth method and the digests of its callbacks, it carries 16 random bytes; without them two registrations of Claude in the same second would get the same id and secret, and anyone posting Claude's body to the open `/register` would hold them.
- **A token carries its tenant, and the address must still belong to it on every request.** `Provider._refusal()` checks the expiry, the 90 days of a sign-in, `MCP_SESSIONS_AFTER`, the scope and the tenant of the address. `load_refresh_token()` also compares the token's client binding with the presenting client: the SDK only compares the client id of the `RefreshToken` it gets back with the request, which the provider fills in itself.
- **`load_access_token()` must never raise.** The bearer middleware runs on every route, the metadata documents included, so an exception there turns every request with a bad `Authorization` header into a `500`.
- **The sign-in has no link, on purpose.** A link that completes a sign-in lets anyone start one for a customer's address from their own Claude account and have an unwary click complete it. The code works only in the window that started the sign-in; a sign-in without a sent mail compares against a value no code matches, so it fails like a wrong code, and the attempts are never reset.
- **Chrome applies `form-action` to the redirect after a form post.** The CSP of the sign-in pages lists the origin of the sign-in's callback next to `'self'`; without it Chrome blocks the `303` back to claude.ai after the code, while Firefox lets it through.
- **The remote server runs as one process, without access log.** Sign-ins in progress and authorization codes live in memory, and uvicorn's access log would print the query string of `/login?txn=`. `main()` also cuts a shutdown to 3 seconds, because Claude holds a `subscriptions/listen` request open for minutes.
- **The tenants file is read twice.** The service and `mcp/accounts.py` parse its `emails` each on their own, and `tests/test_mcp_remote_accounts.py` pins that they map a file alike. The remote server reads the file again when it changes and keeps the addresses read before when the new file is invalid or gone.
- **`bin/test` asks for the SDK by its distribution.** `importlib.util.find_spec("mcp")` finds the folder `mcp/` as a namespace package when the SDK is missing, so it would never report it.
- **The `bin/` scripts run on the bash 3.2 of macOS.** There, an apostrophe in a heredoc inside `$(...)` breaks the parsing of the whole script.
- **The tests of the remote server speak JSON-RPC themselves.** `tests/mcp_remote.py` plays the requests of claude.ai over `httpx.ASGITransport`, the 2026-07-28 envelope with its `Mcp-Method` and `Mcp-Name` headers included: `mcp.Client` reaches an HTTP server through `httpx2`, which the suite does not pin.
- **The version lives in `app/__init__.py` and in `mcp/version.py`,** because `mcp/` must not import `app`. `tests/test_mcp_remote_server.py` fails when the two differ.
- **Python 3.11 is the floor.** Development runs 3.13. `tomllib` is the newest feature in use, and ruff's `target-version` is `py311` so the `UP` rules cannot introduce newer syntax.

## Adding a template

1. Create `<bundle>/<name>/` with `template.toml` (`name` must equal the directory name), `template.html.j2` and `template.css`, in a built-in bundle under `bundles/` or in a bundle of a tenant under `<BUNDLES_DIR>/<tenant>/`. The name follows `^[a-z0-9][a-z0-9-]*$`; a leading `_` marks shared files such as `_base/`. A new bundle also needs a `bundle.toml` with its font faces and checks and its fonts in `fonts/`, see `docs/bundles/README.md`.
2. Declare `formats`, `fields`, `required`, `[defaults]` and `[samples]`. The registry validates that `required`, `defaults` and `samples` only mention declared fields. `[samples]` is the preview content of the debug route and never exposed by the API; it must give every required field a non-blank value, or the registry refuses to start; a default does not count. `headline` is optional in the request model like every other field, so a template that needs one lists it in `required`, as every template of `demo` does. `image = true` additionally lets the template take the request's image; without it an `image` in the request is a `400`. `fallback_image = "<file>"` names an image file in the bundle's `assets/` that is used when the request sends none. `icon = true` lets the template take an SVG `icon` the same way; such a template may not declare a fallback image, or a card with an icon would carry the fallback image as well. `code = true` lets the template take code, which every request must then carry, and needs a `[code_sample]` table with the preview's `code` and optionally its `language`, `line_numbers` and `highlight_lines`. `[limits]` caps declared fields below the service-wide limits, from 1 to 200, and the samples must respect them. The template gets the fonts of its bundle; there is no font setting per template.
3. The template receives `width`, `height`, `format`, `format_token`, `fields`, `image`, `icon`, `code`, `css`, `font_css`, `font_checks` and `fit_text`. `code.html` holds the highlighted lines of a template with `code = true`, see `docs/bundles/README.md` for its markup and token classes. Colors live in the bundle's CSS. In `demo`, extend `_base/base.html.j2`, as every template there does: fill `{% block stage %}`, and where needed `{% block meta_end %}` for the right end of the header row, `{% block backdrop %}` for a full-bleed image and `{% block footer %}` for a row under the stage. Put every fitted element alone in a `.fit-box` wrapper whose `max-height` is the space it gets, mark the element `data-fit="<name>"` and define `--<name>-min` and `--<name>-max`. `template.css` comes after `base.css`, so it overrides the shared rules and the `--color-*` variables every color goes through, and `:root[data-format="1:1"]` scopes a value to one format. A skeleton of your own needs the same readiness gate, font loading and fit-text pass.
4. `GET /v1/templates` picks it up at the next start for every tenant that can use the bundle, and `POST /v1/render` accepts its declared fields. No code change, but every field that is new to the API gets a row in the parameter table of `docs/render.md`, with the templates that declare it: every element on a card is a request parameter, whether or not `RenderRequest` types it.
5. Look at it with the debug route, `/v1/debug/html?template=<bundle>/<name>`, with `&tenant=<tenant>` when there are several, or pick it from the overview at `/v1/debug`, which links every template in every format and variant. The debug route takes every declared field as a query parameter on top of its sample. It calls `TemplateRegistry.render_html`, the same function the screenshot uses.

Logos go into the bundle's `assets/`; `inline_svg("file.svg")` is available as a Jinja global
and inlines the SVG from there, so it stays crisp and can inherit `currentColor`.

## Conventions

- Identifiers, comments, log lines and `docs/` are English. The only user-facing German text is the sign-in page and mail of the remote MCP server, next to their English version in `mcp/login_pages.py`; otherwise German only appears as sample content.
- Error envelope: `{"ok": false, "error": "A full sentence."}`. Error strings end with a period.
- Versioned paths `/v1/<resource>`. `/health` stays unversioned, and so do `/o/…` and `/u/…`, the file URLs the service hands to callers.
- Bearer only. A key in a query parameter is never accepted.
- Dependencies are pinned with `==` in `requirements.txt`; dev-only tools live in `requirements-dev.txt`, the MCP servers' in `requirements-mcp.txt`, which pins everything `mcp/` imports and which `requirements-dev.txt` includes.
- Never log the rendered text, a key, a key hash, a storage credential, a URL the service hands out, or a URL a caller sent and the addresses it resolved to. Tenant name, template, format, headline length, the number of code lines, upload id and sizes are fine. The remote MCP server never logs a token, a sign-in code, a client secret or a full email address; an address masked to its first letter and domain is fine.
- Changing an endpoint means updating the table in `docs/README.md` and the endpoint's own page.
- A feature beyond the HTTP API gets a folder of its own under `docs/`, such as `docs/mcp/`: its implementation plan while it is being built, its documentation as `README.md` once it exists. The API reference stays in `docs/` itself, one page per endpoint.
- Commits follow Conventional Commits (`feat:`, `fix:`, `chore:`).
